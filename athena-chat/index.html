How it works

Click any step to see what actually happens — or click the connectors to step through it like a tour.

Document

Your file (PDF, DOCX, TXT, or MD) is validated for format and size, then hashed with SHA-256 to check whether it's already been indexed before any processing begins.

Chunking

The document is split using a recursive character splitter — 1500 characters per chunk with 150 characters of overlap, so context isn't lost at chunk boundaries.

Embed

Each chunk gets two embeddings: a 768-dim dense vector for semantic meaning, and a sparse SPLADE vector for exact keyword matching — enabling hybrid search later.

Vector DB

Both vectors are stored in Qdrant, tagged with your client ID. Every future query is filtered by that tag, so your documents are never visible to another client.

Query

A visitor asks a question through your embedded chat widget — this is where a real conversation with your chatbot begins.

Embed

The question is embedded the same way your documents were — dense and sparse — so it can be directly compared against what's stored in Vector DB.

Retrieve

Qdrant runs a hybrid search combining both vector types, using Reciprocal Rank Fusion to merge semantic and keyword results into one ranked list of candidate chunks.

Augment

The top-ranked chunks are combined with your original question into a single prompt, with instructions that keep the model from answering outside your documents.

Generate

The prompt is sent to Groq's Llama 3.3 70B model, which generates an answer grounded only in your content — with the source chunks it used.
